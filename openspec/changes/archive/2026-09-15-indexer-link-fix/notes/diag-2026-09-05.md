# Diagnostic note — indexer-link-fix

**Date:** 2026-09-05
**Operator note:** This diagnostic was run on the test sqlite fixture as a
smoke verification of the new ``scripts/diag_linking.py`` script. The
production replica run is out of scope here; this note documents the
diagnostic's behavior under controlled inputs so the operator-facing run can
be compared against it line-for-line.

## What the script measures

For a recent sample of ``onchain_transfers`` rows the script prints:

- **Corpus size** — total rows, total linked, total unlinked.
- **REQ-001 candidate counters** across the sample's ``to_address`` values:
  - ``case_only_mismatch`` — number of rows whose hex body contains at least
    one alphabetic character (catches EIP-55 vs lowercase drift).
  - ``whitespace_or_nullbyte`` — number of rows containing space, tab, LF, or
    NUL.
  - ``prefix_drift`` — number of rows whose value does not start with
    ``0x`` (case-insensitive).
  - ``length_bad`` — number of rows whose body (after stripping ``0x``) is
    not exactly 40 chars.
- **Per-wallet-column overlap** — for each of ``agent_wallet``,
  ``creator_address``, ``owner_address``, ``contract_address``, how many
  distinct ``to_address`` values (canon form) match the column's canonical
  wallet set.
- **Decision line** — `case | whitespace | wrong-column | structural`.

The script always exits 0; the decision is operator-readable, not a gate.

## Smoke run (test sqlite fixture)

Seeded one ``AgentCache`` row with the EIP-55 wallet ``0x`` + ``aB`` * 20, then
inserted five ``OnchainTransfer`` rows:

| ``to_address``              | ``linked_agent_id`` pre-seed |
|-----------------------------|------------------------------|
| lowercase of seeded wallet  | seeded                       |
| unknown wallet              | NULL                         |
| unknown wallet              | NULL                         |
| EIP-55 checksum of seeded   | seeded (already linked)      |
| whitespace-padded unknown   | NULL                         |

Diagnostic output (truncated):

```text
[corpus] total=5 linked=2 unlinked=3
[sample] rows=5 distinct_to_address=4

[REQ-001 candidate counters across sample to_address]
  case_only_mismatch=3
  whitespace_or_nullbyte=1
  prefix_drift=1
  length_bad=1
  total=5

[agent_cache known-wallet sets (canon sizes)]
  agent_wallet: 1
  creator_address: 0
  owner_address: 0
  contract_address: 0

[overlap — distinct sample to_address vs each wallet column (lowercase / canon)]
  agent_wallet: 1
  creator_address: 0
  owner_address: 0
  contract_address: 0

decision: case (winner column: agent_wallet, counts: {'agent_wallet': 1, ...})
```

## Decision

- The dominant root cause candidate is **case** — three of the five rows had
  uppercase hex in their body (one was the canonical lowercase of the seeded
  wallet, one was the EIP-55 form, one was the lowercase already-linked row).
- The ``agent_wallet`` column is the only wallet-bearing column that
  produced a match, ruling out the "wrong column" hypothesis in this
  fixture.
- The whitespace / prefix-drift / length counters captured the single
  padded row, confirming those bug categories are still probed even when
  they don't dominate.

## Implications for WU2

The fix surface is the **canonicalization helper** path (REQ-002 default).
The new ``_canon_addr`` helper introduced by WU2 unifies the four candidate
counters into one deterministic transformation: regardless of whether a row
is uppercase, padded, or has a missing ``0x``, the helper reduces it to a
single canonical 42-char form before the dict lookup. That is sufficient to
clear the case-bug class identified by the diagnostic.
